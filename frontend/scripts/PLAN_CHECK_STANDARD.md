# 重訓課表檢查標準

生成的每一份重訓課表都要通過下面的檢查。每一條寫的是：哪支腳本、規則、教練為什麼在意。
執行方式：在 `frontend/` 底下 `node --import ./scripts/_register_hooks.mjs scripts/<腳本>.mjs`。

## 一堂課的動作順序（教練順序）

這是課表最常被挑的地方，規則只有一套，生成端（`UnifiedTrainingEngine` 輸出後處理 ①.5）跟檢查端（`validatePlan`）用同一個定義：

1. 先做多關節大動作，再做單關節孤立動作，核心收尾，矯正動作最後。
2. 同一個部位的動作排在一起，做完一個部位再換下一個。
3. 唯一允許拆開的情況：先把所有大重量複合做完，再回頭補孤立。
   例：深蹲 → 羅馬尼亞硬舉 → 腿彎舉 → 腿伸展、臥推 → 肩推 → 夾胸。
   條件是同一個部位最多分兩段，第一段只能是複合動作，第二段不能再出現大重量複合（tier 1–2）。
   「臥推 → 夾胸 → 肩推 → 上斜臥推」這種推到一半換部位、再回來推重的，仍然不行。
4. 孤立動作先接最後一個複合動作的那個部位（羅馬尼亞硬舉後先接腿彎舉），不在背的動作中間插一個後三角。
5. 非手臂日，二頭和三頭放在胸、背、肩、腿都做完之後。
6. 不屬於這一天的部位（例：推日被補進來的腿或臀），排在同一類動作的最後：推日先做胸和肩的複合，再做補進來的腿；不會一開始就做臀推。
7. 超級組（A＋B）當成一個單位，一起移動，不會被拆開。

## 硬傷稽核：`validatePlan`

腳本：`audit_unified_legislation.mjs`（1008 種組合）、`audit_strength_integrity.mjs` 的 `internal_validator`。

| 規則 | 教練為什麼在意 |
|---|---|
| 分化純度：推日沒有背和二頭，拉日沒有胸和三頭，腿日沒有上半身 | 練到隔天要休息的部位，恢復被打亂 |
| 每天動作數不超過等級上限（新手 3、中階 4、高階 6） | 做不完，品質下降 |
| 群聚：同一部位排在一起（只允許上面第 3 點的兩段式） | 一個部位做到一半換掉，泵感和專注都斷掉 |
| 核心收尾 | 核心先累，後面的深蹲、硬舉撐不住軀幹 |
| 同部位裡，孤立動作不能排在複合之前；同類動作 tier 不能倒過來 | 先把肌肉磨累再推重，推不動又容易受傷 |
| 新手：不用槓鈴、不做極限 CNS 動作、不做遞減組、不開 3–5 下 | 新手先學動作模式 |
| 超級組數量不超過等級上限 | 太多超級組，整堂課都在喘 |

## 重訓引擎修正驗證：`verify_strength_fixes.mjs`

| 規則 | 教練為什麼在意 |
|---|---|
| S-01 減量週不做遞減組 | 減量週是用來恢復的 |
| S-02 換成器械版本時，仍然要避開關節限制清單和難度上限 | 換動作不能繞過安全規則 |
| S-06 高 CNS 日動作數要扣：同一天有 2 個大重量複合時上限 −1，3 個以上時上限 −2（不低於等級下限，實際上只會影響高階） | 一天兩三個大重量，神經系統已經吃滿，不要再多塞動作 |
| S-03 有體重時新手拿到自由重量的建議重量；機械和繩索不給數字，改給「怎麼挑重量」 | 各廠的配重不一樣，算出來的數字是假的精確 |

## 一週一天的課表：`verify_strength_coverage.mjs`

| 規則 | 教練為什麼在意 |
|---|---|
| 不選部位或胸背腿都選，一週只練一天時，四週每一週都要有下肢、推、拉 | 一週只有一次機會，不能有一週漏掉胸 |
| 只選腿：四週都不能出現胸和背 | 使用者明確只要下肢 |
| 時間有沒有超過預算，旗標要跟實際分鐘數一致 | 畫面上的提示不能說錯 |

## 課表資料完整性：`audit_strength_integrity.mjs`

| 規則 | 教練為什麼在意 |
|---|---|
| 一定是 4 週、天數正確、沒有空的一天 | 基本結構 |
| 同一天不重複同一個動作 | 重複等於少練一個角度 |
| 一天最多一個極限 CNS 動作，也不連兩天 | 背蹲和硬舉連兩天，下背和神經都恢復不了 |
| 顯示的時間等於重算的時間 | 數字要誠實 |
| 處方完整（組數、次數、休息）；徒手環境只有徒手和彈力帶；減量週沒有遞減組 | 學員照著做不會卡住 |
| 超級組一定是兩個一組、輪數一樣、不會兩個都是高 CNS | 一個人的超級組沒辦法做；A 做 3 輪、B 做 2 輪也排不起來 |
| （目前只列出不擋）時間超過選的時長 5 分鐘以上 | 待定的產品規則：高階一天至少 5 個動作，選 30 分鐘時排不進去 |

## 教練逐項檢查：`verify_coach_plans.mjs`（加 `--full` 會跑兩處以內的關節限制組合）

| 規則 | 教練為什麼在意 |
|---|---|
| 3 天以上是推、拉、腿；2 天是上、下半身；同一種日子不連著排 | 同部位要隔 48 小時 |
| 選的重點部位一週練 2 次（4 天一個重點、5 天每個重點），重點部位在它自己那天至少 2 個動作 | 頻率是長肌肉的關鍵 |
| 第一個動作是複合；手臂在大肌群後；核心最後；tier 1 不排在輕動作後 | 精神最好的時候做最重的 |
| 同部位同類型不重複；每個部位一天的動作數有上限 | 同一個刺激不做兩遍 |
| 次數：肌肥大複合 5–15 下；力量主項不超過 8 下；新手選力量時複合不超過 10 下 | 次數要對得上目標 |
| 休息：主項至少 90 秒，孤立不超過 120 秒；遞減組只用在器械或啞鈴的孤立動作，最多 2 輪，一天最多 1 個 | 休息太短做不起來，太長浪費時間 |
| 高峰週一天最多 2 個大重量；減量週總組數比基礎週少 | 週期要真的有起伏 |
| 重點部位每週組數有下限，任何部位一週不超過 20 組，推拉比不超過 1.6 | 量太少沒效果，太多恢復不了，推拉失衡會圓肩 |
| 有練腿就要有髖鉸鏈；背是重點時，垂直拉和水平拉都要有 | 動作模式要完整 |
| 中高階肌肥大：同一週兩天不共用 2 個以上一樣的動作 | 第二次練同部位要換角度 |
| 沒選的胸、背、股四頭也要練到（沒選不等於不練） | 全身平衡 |
| 新手不上槓鈴，不做極限動作 | 安全 |
| 動作庫的部位對應和圖片都要對 | 畫面不能配錯圖 |

## 教練眼掃描：`verify_plan_coach_eye.mjs`（9504 份課表 × 4 週；加 `--quick` 只跑一半）

窮舉：等級 × 一週 1–6 天 × 健身房、混合、徒手 × 兩種風格 × 11 組常見重點 × 無傷、膝、肩、下背 × 45 和 60 分鐘。

| 代碼 | 規則 | 教練為什麼在意 |
|---|---|---|
| E1 | 同一天不重複同一個動作 | 等於少一個動作 |
| E2 | 大重量複合不排在同部位的孤立之後 | 先磨累再推重，推不動也容易受傷 |
| E3 | 同一天同一個動作模式不超過 2 個（例：三個水平推） | 同一個刺激做三遍 |
| E4 | 一天不能只有孤立動作 | 每天都要有一個多關節主項 |
| E5 | 槓鈴或極限 CNS 的複合不開超過 12 下 | 重量會輕到失去主項的意義，高次數時技術最容易散 |
| E6 | 新手不排引體向上和反手引體；中階引體不超過 10 下 | 拉自己的體重，寫 12–15 下做不到 |
| E7 | tier 1 大複合至少休 90 秒；孤立不超過 120 秒 | 休息要對得上動作 |
| E8 | 關節限制清單裡的動作不出現 | 安全 |
| E9 | 徒手環境只有徒手和彈力帶 | 在家沒有器材 |
| E10 | 每個動作都有組數、次數、休息 | 學員照著做不會卡住 |
| E11 | 新手沒有 6 下以下、沒有遞減組、沒有槓鈴 | 新手先學動作 |
| E12 | 每天動作數在等級區間內 | 太少是空堂，太多做不完 |
| E13 | 超級組兩個一組、相鄰、輪數一樣，不會兩個都是高 CNS | 排得出來，也不會把神經系統打爆 |
| E14 | 一天最多一個極限動作，也不連兩天 | 背蹲和硬舉要隔開 |
| E15 | 下背承重的鉸鏈（硬舉、羅馬尼亞硬舉、早安）不連三天 | 下背累積疲勞 |
| E16 | 四週用同一套動作，只有組數、次數、休息跟著週期變 | 一個週期內換動作，進步沒辦法比，新手更要重複 |
| E17 | 減量週組數不比第 1 週多、沒有遞減組；強化週次數不比第 1 週高 | 週期的方向不能反過來 |
| E18 | 選的重點部位四週每一週都有練到（選手臂時二頭、三頭都要有；關節限制把整個部位封掉的除外） | 選了卻沒練，使用者會覺得被騙 |
| E19 | 高峰週一天最多 2 個 3–5 下的大重量 | 神經疲勞恢復不了 |
| E20 | 同一個 tier 1 主項不排在連續兩天（第二天換同部位的變化） | 同一個動作要隔 48 小時 |
| E21 | 每個部位一週不超過 20 組 | 超過恢復跟不上 |

## 新手規則（全部腳本共同）

新手在任何組合下都不會出現引體向上和反手引體（`STRICT_BW_PULLS`，由 `passesLevelGate` 擋，E6 檢查）。

## 課表周邊流程

這些腳本不檢查動作本身，檢查的是課表存檔、完成紀錄、換季這些流程有沒有改壞：

| 腳本 | 檢查什麼 |
|---|---|
| `verify_strength_persistence.mjs` | 存檔時帶上週期起點和排好的星期；斷線或伺服器沒回 ID 時一定報錯並留下待補送；完成一天只記一次 |
| `verify_strength_completion.mjs` | 完成紀錄跟著課表走，切換課表不會把舊紀錄復活 |
| `verify_program_consistency.mjs` | 回應不確定時重送、帳號之間隔離、草稿救回、週期回饋 |
| `verify_season_transition.mjs` | 換季預告清單和實際寫進課表的改動一致；換動作不會把健身房課表換成彈力帶 |
| `verify_season_redesign_roundtrip.mjs` | 季末換部位重排，摘要只寫真的有改的 |
| `verify_gym_memory.mjs` | 依健身房換動作：這間沒有的器材一定被換掉，組數和次數保留 |
| `verify_cycle_recommendation.mjs`、`verify_cycle_baseline.mjs` | 建議的週期和起點來自真實量測 |
| `verify_coach_science.mjs` | 教練文案對得上運動科學規則（恢復 48–72 小時等） |
| `verify_spec_v2b.mjs`、`verify_staged_path.mjs` | 規格文件條目、路徑卡數字加得起來 |
